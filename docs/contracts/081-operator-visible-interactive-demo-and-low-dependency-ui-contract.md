## Purpose

Freeze the rule for the next post-readiness demo stream: Signal should expose
operator-visible interactive proof for the functionality each crate claims,
while avoiding a new heavyweight in-repo UI dependency stack.

## Authority hierarchy

1. each crate still owns the behavior its interactive demo claims
2. shared demo substrate owns manifest, launch, scenario, and evidence
   conventions
3. this contract owns the interaction model and low-dependency UI posture
4. downstream product shells remain out of scope

## Required operator-visible guarantees

- interactive demos must let an operator directly observe the claimed behavior,
  not only read receipts after the fact
- where the domain is naturally interactive, the operator should be able to
  drive it live:
  - browse installed plugins
  - launch or attach to a supported plugin host path
  - manipulate parameters or scenarios
  - observe resulting state, receipts, or media output
- where the domain is not naturally live-hosted, the operator should still get
  an inspectable visual or structured surface rather than raw log spam alone

## Low-dependency UI rules

- do not add heavyweight product-style UI frameworks just to make demos look
  polished
- prefer one of these proof surfaces, in order:
  - existing host or example binaries with bounded operator prompts
  - static HTML/CSS/JS or browser-native assets generated by repo-owned
    commands
  - terminal or TUI surfaces that stay small and self-contained
  - machine-readable receipts paired with lightweight rendered summaries
- if a richer UI runtime is proposed later, it must be justified as shared
  Signal-owned proof infrastructure, not aesthetic convenience

## Required proof posture

- every crate should map to either:
  - an existing live demo that already supports direct operator inspection, or
  - a named planned interactive surface that closes the remaining visibility gap
- plugin-format demos must clearly distinguish:
  - discovery and browsing
  - instantiation and lifecycle
  - live interaction
  - explicit exclusions by host/backend/platform

## Non-Goals

- building a downstream DAW-like product shell inside Signal
- replacing acceptance tests with manual demo workflows
- requiring one uniform UI modality across all crate families

## Next Task

Use this contract as the benchmark if a future generation proposes additional
operator-visible demo work beyond the closed `g09.015` lane.
