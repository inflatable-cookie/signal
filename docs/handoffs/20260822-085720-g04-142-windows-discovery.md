## Boundaries

- **In scope (contract 087, exactly):** `ClapHostPlatform::Windows`;
  default roots `%COMMONPROGRAMFILES%\CLAP` then
  `%LOCALAPPDATA%\Programs\Common\CLAP`; `CLAP_PATH` append with `;` as
  the Windows separator (`:` elsewhere); flat `.clap` (DLL) units only —
  no Windows directory-bundle convention; environment-variable expansion
  in roots handled by the adapter like `~` on Unix. Plus VST3: fixture
  tests proving Windows default roots and
  `Contents/{x86_64,arm64}-win` bundle resolution.

  macOS/Linux discovery semantics; Soundcheck or library edits; a Signal

  mutations.

  and vice versa.

## Important Context

- **Separator subtlety:** `CLAP_PATH` splitting is platform-dependent for
  the first time (`;` on Windows). Make the split a function of the
  platform parameter, not of the compile target, so the
  platform-parameterized tests can cover both separators on any host.
- **Fixture note:** `compile_clap_fixture` emits a cdylib named `*.clap` —
  on any host that file satisfies the Windows flat-unit shape for
  discovery-path tests (dlopen-level tests stay target-native, as the
  Linux tests did).
- **Report after:** each meaningful chunk (CLAP roots, unit resolution,
  VST3 verification), or immediately on any blocker.
- **Report to:** the operator, who relays to the orchestrator.
