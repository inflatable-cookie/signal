# Backlog: Post-g08 Repeated-Run, Environment-Matrix, And Downstream Workflow Depth

Status: backlog
Priority: medium
Estimated effort: multi-batch generation
Source: g08.020

## Problem

`g08` closes the bounded live-ownership and workflow expansion queue with one
repo-owned integrated acceptance and closeout gate, but several credible next
steps remain deliberately outside that finished bar:

- broader repeated-run confidence over the bounded integrated acceptance lane
- richer environment-specific matrices across Linux sessions, devices,
  immersive paths, and preview or workflow mixes
- stronger shared downstream workflow hardening beyond the current bounded
  closeout-ready substrate

If those scopes remain implicit, later work risks reopening `g08` piecemeal or
smuggling broader environment and workflow expectations into product-local
launch decisions.

## Proposed approach

Open the next generation only when maintainers want to promote those deferred
scopes without reopening backend-local, browser-local, device-private, or
renderer-private policy.

Keep the next queue inside Signal-owned reusable boundaries:

- promote repeated-run and environment-matrix depth only where the resulting
  evidence can stay typed, machine-readable, and repo-owned
- decide which currently bounded integrated acceptance lanes should become
  stronger shared gate evidence and which should remain advisory
- harden Linux live, device workflow, immersive monitoring, and preview
  workflow acceptance only where the depth still reflects reusable Signal
  substrate instead of downstream launch choreography
- keep product-local controller, browser, immersive-console, certification, and
  downstream launch workflows explicitly deferred unless they become reusable
  shared boundaries first

## Promotion trigger

Promote this backlog item when at least one of the following becomes true:

- maintainers want broader repeated-run confidence beyond the bounded `g08`
  closeout fast path
- environment-specific Linux, device, immersive, or preview matrices become
  important enough to promote into shared acceptance evidence
- downstream teams need stronger shared workflow hardening without reopening
  product-local policy shells

## Success criteria

- [ ] the next generation names which deferred `g08` scopes are being promoted
- [ ] stronger rerun or environment-matrix depth remains tied to shared Signal
      receipts, descriptors, and Effigy tasks
- [ ] broader workflow hardening does not reintroduce backend-local,
      browser-local, renderer-private, or device-private orchestration shells

## Risks

- repeated-run and environment-matrix work can sprawl into expensive
  certification inventory rather than shared bounded evidence
- downstream workflow hardening can drift into product-local launch or UX
  policy instead of reusable runtime substrate
- broader integrated acceptance can become opaque if it stops emitting typed
  descriptors and collapses back into ad hoc scenario bundles

## Next Task

Promote this backlog item only when maintainers want stronger repeated-run
confidence, broader shared environment matrices, or deeper shared downstream
workflow hardening beyond `g08`'s bounded closeout gate.
