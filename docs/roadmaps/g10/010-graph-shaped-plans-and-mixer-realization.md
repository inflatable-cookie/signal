## Problem

The render plane is a flat stereo lane/clip player: lanes sum straight into
the callback buffer, there is no pan (identical samples on both channels),
no busses, no sends, no solo/mute semantics, and `channels.min(2)` bakes in
the stereo assumption. Pulse's console model (channel chains, busses, sends)
renders knobs in Aura that move no audio beyond lane gain. Every future
feature — inserts, sends, PDC, metering targets, automation targets — needs
node addresses that do not exist.

The control/render split accommodates this unchanged: a compiled DAG is
still an immutable plan; the mailbox/retire lifecycle stays.

## Goals

- [x] compiled node schedule: lane → bus → master as a topologically-ordered flat execution list (indices, not pointers), scratch buffers owned by the plan (the buffer pool IS the plan, preallocated at compile)
- [x] mix-matrix node primitive (N×M gain matrix applied per frame, alloc-free); stereo pan = the 1×2/2×2 case generated by an equal-power coefficient law — per chorus a14, spatial control is a matrix, never a baked end-of-chain knob
- [ ] mute/solo realized at compile (deferred: pulse console model still lane-shaped — lands with pulse-side bus/send compilation) (pulse decides audibility; plan carries resolved gains) with declick via the existing gain smoothing
- [x] sends as extra schedule edges (post-fader tap + gain) feeding bus nodes
- [x] channel FORMAT carried per edge (count + layout semantics, extensible past stereo from day one); scratch buffers sized by edge format; kill the channels.min(2) stereo bake-in
- [x] hardware-stage downmix boundary: plan renders at the master format; the executor downmixes to the negotiated stream format with standard coefficients only when the device is narrower — never inside the creative graph
- [x] pulse compiles its console model (lanes→master; bus/send compilation follows when pulse exposes it) into the new plan vocabulary
- [x] golden-file render test harness: plan in, hashed PCM out, gating every render-plane change from now on
